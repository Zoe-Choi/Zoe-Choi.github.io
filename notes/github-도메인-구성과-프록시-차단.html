프록시 설정 확인

정리 2026-07-28

한 줄 정의

github.com은 HTML만 주고 CSS/JS/이미지/API는 전부 별도 도메인에서 오므로, 프록시가 github.com만 허용하면 화면이 스타일 없는 순수 HTML로 깨진다.

자세히

도메인별 역할:

도메인역할막히면
github.comHTML 페이지, git over HTTPS (clone/push)접속 자체 불가
github.githubassets.comCSS, JS, 폰트, 아이콘 (정적 자원 CDN)화면이 스타일 없이 깨짐
api.github.comREST API (JSON). gh CLI, Actions, IDE 연동gh 명령, 자동화 스크립트 실패
raw.githubusercontent.com파일 원본 직접 조회 (Raw 버튼)raw 다운로드, curl 설치 스크립트 실패

핵심 구분:

  • git 명령은 github.com만 사용. 웹 UI가 깨져도 clone/push는 정상.
  • 아카이브 다운로드(codeload)는 git 프로토콜이 아니라 별도 HTTP 경로.
  • *.githubusercontent.com 와일드카드 한 줄로 대부분 커버 가능.

왜 중요/어디서 씀

사내 프록시 화이트리스트 방식(squid 등)에서 github.com만 등록하는 실수가 흔하다. 증상이 "GitHub 화면이 깨짐"으로 보여 브라우저 문제로 오해하기 쉽지만, 실제로는 정적 자원 도메인 403 차단이다.

차단 판별법: 응답 헤더에 X-Squid-Error: ERR_ACCESS_DENIED가 있으면 프록시 차단이다.

# 프록시 설정 확인
Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' |
  Select-Object ProxyEnable, ProxyServer, AutoConfigURL, ProxyOverride

# 도메인별 차단 여부
try { Invoke-WebRequest 'https://github.githubassets.com/assets/light.css' -UseBasicParsing }
catch { $_.Exception.Response.Headers['X-Squid-Error'] }

예시

GHES(GitHub Enterprise Server) 온프레미스는 이 문제가 없다. 자기 호스트에서 정적 자원과 API를 모두 서비스한다.

  • 정적 자원: <GHES호스트>/assets/, CSP가 script-src 'self', style-src 'self'
  • API: https://<GHES호스트>/api/v3 (github.com은 api.github.com)
  • 외부 의존은 GitHub Connect 연동 기능(릴리스 에셋 S3, githubstatus.com) 정도만 남음

따라서 외부 GitHub 웹 UI가 프록시 때문에 깨지는 환경에서도 사내 GHES는 정상 렌더링된다.
