NameNode 힙과 DataNode 메모리

정리 2026-09-10

한 줄 정의

NameNode 힙은 파일과 블록의 개수에 비례하는 메타데이터 저장 공간이고, DataNode 서버의 물리 메모리는 사실상 같은 노드의 YARN NodeManager 컨테이너용이다. 둘은 해결하는 문제가 다르다.

자세히

NameNode

HDFS의 네임스페이스 전체를 메모리에 상주시킨다.

  • 디렉터리 트리, 파일명, 권한, 파일별 블록 목록, 블록별 위치(DataNode)
  • 디스크의 fsimage와 edits는 재시작 복구용이고, 운영 중 조회는 100% 메모리에서 처리
  • 힙 소요는 데이터 용량이 아니라 오브젝트 개수에 비례. 오브젝트 하나당 약 150 bytes
  • 경험칙: 오브젝트 100만 개당 힙 약 1GB
  • 1TB 파일 하나는 메모리를 거의 안 쓰고, 1KB 파일 100만 개는 힙을 크게 먹는다. 이것이 small files problem

힙이 부족하면 full GC로 NameNode가 멈추고, 그동안 HDFS 전체가 응답하지 않는다. OOM이면 HDFS 전면 중단.

설정 위치는 hadoop-env.sh의 HDFS_NAMENODE_OPTS(Hadoop 3) 또는 HADOOP_NAMENODE_OPTS(Hadoop 2). 변경하려면 NameNode 재시작이 필요하고, HA가 없으면 클러스터 전면 중단이다.

DataNode

블록을 로컬 디스크에 저장하고 읽기/쓰기를 서빙한다. 블록 리포트를 NameNode에 보내고 replication을 수행한다.

  • 데몬 자체는 메모리를 거의 안 쓴다. 보통 힙 1-4GB면 충분
  • 힙은 관리하는 블록 수에 비례하지만 NameNode보다 훨씬 완만
  • 데이터를 메모리에 캐싱하지 않고 디스크에서 직접 스트리밍 (HDFS centralized cache를 명시적으로 켜지 않는 한)
  • 설정 위치는 HDFS_DATANODE_OPTS

따라서 워커 노드에 RAM을 증설하는 이유는 DataNode 데몬 때문이 아니라 같은 서버에 뜨는 YARN NodeManager 때문이다. 실제 소비처는 Spark executor 컨테이너다.

정리

대상무엇에 비례부족하면늘리는 방법
NameNode 힙파일 + 블록 개수GC 정지, HDFS 전면 중단HDFS_NAMENODE_OPTS, NameNode 재시작
DataNode 힙블록 개수 (완만)드묾HDFS_DATANODE_OPTS
워커 노드 물리 RAM동시 실행 Spark executorjob OOM, 컨테이너 대기yarn.nodemanager.resource.memory-mb, NM rolling restart

왜 중요/어디서 씀

물리 메모리를 증설해도 yarn.nodemanager.resource.memory-mb를 올리고 NodeManager를 재시작하기 전까지 YARN은 그 메모리를 쓰지 않는다. 정적 설정값이다.

증상으로 구분한다.

  • Spark job이 OOM으로 죽거나 컨테이너가 대기 → 워커 노드 RAM / YARN 설정
  • NameNode GC가 길어지거나 힙 사용률이 높음 → NameNode 힙, 또는 파일 개수 자체를 줄이기

예시

Iceberg 시험 적재로 파일이 83만 개 생긴 경우, NameNode 힙을 올리는 것보다 compaction(rewrite_data_files)으로 파일 개수를 줄이는 쪽이 근본 해결이다. 힙 증설은 재시작이 필요하고 파일이 더 늘면 다시 막힌다.

현황 확인은 NameNode JMX로 무중단 조회할 수 있다.

curl -s 'http://<nn>:9870/jmx?qry=Hadoop:service=NameNode,name=FSNamesystem' \
 | python3 -c "import sys,json;d=json.load(sys.stdin)['beans'][0];print('files',d['FilesTotal'],'blocks',d['BlocksTotal'])"

curl -s 'http://<nn>:9870/jmx?qry=java.lang:type=Memory' \
 | python3 -c "import sys,json;h=json.load(sys.stdin)['beans'][0]['HeapMemoryUsage'];print(h['used']//2**20,'MB /',h['max']//2**20,'MB')"

yarn node -list -showDetails
