Airflow warn_deployment_exposure

정리 2026-09-03

한 줄 정의

Airflow webserver가 /robots.txt 요청을 받으면 "이 배포가 인터넷에 노출된 것 같다"고 UI에 띄우는 경고. [webserver] warn_deployment_exposure = False로 끈다.

자세히

/robots.txt는 사람이 브라우저로 Airflow UI를 쓸 때는 요청하지 않는 경로다. 검색엔진 크롤러와 인터넷 스캐너만 습관적으로 찾는다. Airflow는 이 경로 요청을 카나리로 보고, 요청이 들어오면 외부에서 도달 가능한 상태로 추정한다.

추정이므로 오탐이 있다:

  • 사내 취약점 스캐너, 자산/ASM 스캔 도구
  • 리버스 프록시나 로드밸런서 헬스체크 경로 오설정
  • 브라우저 확장, 사내 프록시의 프리페치

설정 위치는 Airflow 2.x 기준 [webserver] 섹션이다. Airflow 3.x는 webserver가 API server로 대체되면서 옵션 구성이 달라지므로 airflow version 확인 후 문서를 본다.

왜 중요/어디서 씀

Airflow UI는 DAG 트리거, Variable 조회, 태스크 로그 열람이 가능한 관리 콘솔이다. 인터넷 노출 시 Connection/Variable의 접속정보 유출과 임의 잡 실행으로 이어진다. 경고를 끄는 것은 조치가 아니다. 노출 여부 확인이 먼저다.

예시

접근 출처 확인. source IP와 User-Agent를 본다:

grep "robots.txt" <webserver access log>

[webserver] access_logfile 기본값이 -(stdout)이므로 systemd 운영이면 journalctl -u <unit> | grep robots.txt로 본다.

바인딩과 진입 경로 확인:

ss -tln | grep 8080
grep -E "web_server_host|web_server_port|base_url" airflow.cfg

0.0.0.0 바인딩 자체는 노출이 아니다. 방화벽, NAT, 리버스 프록시 경로를 함께 봐야 판정된다.

경고만 끄기. webserver 재시작이 필요하므로 서비스 중단을 수반한다:

[webserver]
warn_deployment_exposure = False
